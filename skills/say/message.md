# Message

## Before you write

1. Read the last ten or so messages where it will land, including what the
   user already posted. Never ask for something they already asked for.
2. Decide who it is for. Tag only the people who must act.
3. A new topic is a new top-level post, not a reply in an old thread.

## Shapes

- Review ask: the reviewers, the ask, the raw PR URL, then one short line
  saying what it is.
- Several PRs: one opening line, then a bullet per PR with its URL and a short
  phrase, grouped by the user's own workstreams.
- Bug-fix reply in the reporter's thread: the cause in one clause, what the
  reporter saw, then the fix and its link.
- Status plus ask: one or two lines of status, then the ask.
- Sharing something the user built: start with the problem it solves, present
  it as an experiment, end by asking what people think.
- A decision on work the user owns: the plan in plain bullets, and "flag if
  anything looks off". State decisions. Don't reopen settled ones.

## Voice

Match the user. If `examples.md` exists beside this file, it holds messages
they sent or approved: find the closest one and match its length and shape.

- Whole sentences in a casual register. Short does not mean clipped.
- Names and proper nouns keep their capitals.
- Offer work to a teammate. Never assign it.
- State a cause you have not proven as "seems".
- No filler, no sign-off, no list of everything you checked.

## Draft or send

The message goes through the app's own tool, in the right channel or thread.
Showing it only in chat does not count.

- The user says send, post, reply or bump: send it.
- They say draft, or don't say: save a draft and tell them where it is, in one
  line.
