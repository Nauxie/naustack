# Message

## Before you write

1. Read the last ten or so messages where it will land, including what the
   user already posted. Never ask for something they already asked for. For a
   review ask, search for the PR first: asks often land in more than one place.
2. Decide who it is for. Tag only the people who must act, with real mentions:
   a typed "@name" sent through a tool often notifies nobody.
3. A new topic is a new top-level post, not a reply in an old thread.
4. Review asks go only where engineers review code. A product or design thread
   gets no PR link and no review ask, even when the PR answers it.
5. Say who is doing what only when someone said it in those words.

## Shapes

- Review ask: the reviewers, the ask, then each PR as a bullet: raw URL and a
  few words. A first ask for a PR that answers a report or ticket opens by
  linking it. Bumps don't repeat that.
- Many PRs: grouped by the user's own workstreams, reviewers tagged on each
  group's line, never telling readers how the message is organized.
- After a review: a few words in the thread ("approved"), or a reaction.
- Bug-fix reply in the reporter's thread: the cause in one clause, what the
  reporter saw, then the fix and its link.
- Status plus ask: one or two lines of status, then the ask. If their agent
  can do it, add a short prompt they can paste.
- Status update on the user's work: one line on what they did and why, then
  what changed in the reader's terms, not internal names.
- A possible bug in a teammate's PR: one plain sentence on what goes wrong, a
  tiny example, the link, and an offer to look into it.
- A problem and some ideas: an invitation to discuss, not a report. The plain
  fact first, then only what the reader needs, then the questions.
- A decision on work the user owns: the plan in plain bullets, and "flag if
  anything looks off". State decisions. Don't reopen settled ones.
- Replying to several points: quote each and answer under it.

## Draft or send

The message goes through the app's own tool, in the right channel or thread.
Showing it only in chat does not count.

- The user says send, post, reply or bump: send it. Read back anything that
  must render right.
- They say draft, or don't say: save a draft and tell them where it is, in one
  line.
- Many apps keep one draft per thread, and a second save can silently replace
  the first. Two messages due in one place go in one combined draft.
- Drafts can't be read back and users send them soon. Never call one unsent
  later: read the thread for what was posted.
